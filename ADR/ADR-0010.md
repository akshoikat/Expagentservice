
### ADR-0010 — Shared Kernel Policy

**Status:** Approved

**Decision**

`packages/shared` শুধুমাত্র framework-agnostic এবং business-neutral component ধারণ করবে। কোনো business service, repository, provider implementation বা domain logic এখানে রাখা যাবে না।

**Reason**

* Shared package-কে dumping ground হওয়া থেকে রক্ষা করা।
* Domain coupling কমানো।
* Module ownership পরিষ্কার রাখা।
* Long-term maintainability নিশ্চিত করা।
* Future refactoring সহজ রাখা।

**Allowed Components**

* `contracts/`
* `types/`
* `errors/`
* `events/`
* `value-objects/`
* `utils/`

**Forbidden Components**

* Domain Services
* Business Logic
* Repository Implementations
* Database Access
* Provider Implementations
* Workflow Logic
* Agent Logic
* Communication Logic

**Migration Strategy**

যদি ভবিষ্যতে `packages/shared`-এ কোনো domain-specific code চলে আসে, তাহলে সেটি সংশ্লিষ্ট domain module-এ স্থানান্তর করা হবে। Shared package সর্বদা business-neutral থাকবে।

---

এখন আমাদের architecture-এর foundation যথেষ্ট mature হয়েছে। সামনে আমরা যে document-গুলো তৈরি করব, সেগুলো আর ধারণাগত (conceptual) থাকবে না—প্রতিটিই সরাসরি implementation guide হবে।

আমার পরিকল্পনা হবে:

1. **PDS-04:** System Context (C4 Level 1)
2. **PDS-05:** Container Architecture (C4 Level 2)
3. **PDS-06:** Repository & Folder Structure (VS Code implementation)
4. **PDS-07:** Database Design (ERD + ownership)
5. **PDS-08:** Event Architecture
6. **PDS-09:** API Design

এই sequence-এর কারণ হলো, আমরা **outside → inside** design করব। আগে পুরো system boundary, তারপর containers, তারপর modules, তারপর database, তারপর events, তারপর API। এতে প্রতিটি layer আগের layer-এর উপর ভিত্তি করে তৈরি হবে এবং মাঝপথে বড় refactor-এর সম্ভাবনা অনেক কমে যাবে।
