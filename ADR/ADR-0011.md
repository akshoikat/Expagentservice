🔒 ADR-0011 — Unified Channel Gateway

Status: Approved

Decision

সব communication provider (WhatsApp, Facebook Messenger, Instagram, Telegram, Gmail, Live Chat ইত্যাদি) একটি Unified Channel Gateway-এর মাধ্যমে Platform-এ প্রবেশ করবে।

Communication Module কখনো কোনো provider SDK বা webhook payload সরাসরি handle করবে না।

Responsibilities

Channel Gateway-এর কাজ হবে:

Provider webhook receive করা।
Signature verification (যদি provider support করে)।
Payload normalize করা।
Contact identify বা create করা।
Conversation identify বা create করা।
Canonical event publish করা।
Duplicate webhook detect করা।
Channel metadata attach করা।
Non-Responsibilities

Channel Gateway কখনো করবে না:

AI invoke
Workflow execution
Business rules
Memory update
Knowledge search
Reply generation

এগুলো Communication Module-এর পরের layer-এর দায়িত্ব।

Canonical Message Model define করা হোক।

কারণ WhatsApp, Messenger, Telegram, Gmail—সবার payload আলাদা।

আমরা যদি provider payload business layer পর্যন্ত নিয়ে যাই, তাহলে পুরো codebase provider-specific হয়ে যাবে।

অর্থাৎ Communication Module সবসময় একই message structure দেখবে।

উদাহরণ হিসেবে একটি canonical model হতে পারে:

interface IncomingMessage {
  id: string;
  workspaceId: string;
  channel: "whatsapp" | "messenger" | "telegram" | "gmail";
  contactId: string;
  conversationId?: string;
  type: "text" | "image" | "audio" | "video" | "document" | "location";
  content: unknown;
  metadata: Record<string, unknown>;
  receivedAt: Date;
}

এর ফলে Channel Gateway-এর পরে পুরো platform provider-independent হয়ে যাবে।

আমি আরেকটি architectural proposal দিতে চাই

আমার মতে আমাদের Communication Module-এর lifecycle-ও state machine হিসেবে design করা উচিত।
