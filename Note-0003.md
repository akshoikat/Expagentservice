# ADR-0012 — Blueprint-Based Agent Architecture

**Status:** Approved

## Decision

The platform will use a single, generic **Agent Runtime**. Business-specific AI agents will not have separate runtime implementations. Instead, every AI professional (e.g., Social Media Manager, Hotel Receptionist, Medical Receptionist, Customer Support Agent, Booking Agent) will be represented as an **Agent Blueprint**.

The Agent Runtime is responsible only for execution. It contains no business-specific behavior.

## Agent Blueprint

An Agent Blueprint is a declarative configuration that defines how the runtime should behave.

Each Blueprint contains:

* Persona
* Instructions
* Knowledge Sources
* Memory Strategy
* Tool Set
* Workflow Rules
* Safety Policies
* Channel Permissions
* Model Configuration

## Architecture

```text
                Agent Runtime
                      │
                      ▼
               Agent Blueprint
                      │
        ┌─────────────┼─────────────┐
        ▼             ▼             ▼
    Persona      Knowledge      Memory
        │             │             │
        ├─────────────┼─────────────┤
        ▼             ▼             ▼
     Tools       Workflows      Policies
                      │
                      ▼
               Runtime Execution
```

## Examples

A **Hotel Receptionist** is not a different runtime.

It is an Agent Blueprint composed of:

* Hotel Persona
* Hotel Knowledge Base
* Hotel Tool Set
* Hotel Workflow Rules
* Hotel Safety Policies
* Hotel Memory Strategy

A **Social Media Manager** uses the same runtime with a different Blueprint:

* Brand Persona
* Brand Knowledge
* Social Media Tools
* Publishing Workflow
* Moderation Policies
* Conversation Memory Strategy

The same pattern applies to:

* Medical Receptionist
* HR Recruiter
* Sales Assistant
* Customer Support
* Real Estate Assistant

## Benefits

* One runtime for every business domain.
* No business-specific execution engine.
* New AI roles can be created through configuration instead of new code.
* Marketplace-ready architecture.
* Blueprint versioning becomes straightforward.
* Import/export and cloning are simplified.
* Consistent execution lifecycle across all AI agents.

## Database Direction

Business agents will be represented by Blueprint-related entities rather than separate agent implementations.

Example:

```text
agent_blueprints
persona_links
knowledge_links
tool_links
workflow_links
policy_links
memory_profiles
```

## UI Direction

Instead of creating a new "Hotel Agent" or "Medical Agent", users create or deploy an **Agent Blueprint**.

Example actions:

* Create Blueprint
* Edit Blueprint
* Clone Blueprint
* Version Blueprint
* Deploy Blueprint
* Archive Blueprint

## Future Capabilities

The Blueprint architecture naturally enables:

* Blueprint Marketplace
* Blueprint Templates
* Version Control
* Import / Export
* Sharing
* Organization Libraries
* Team Collaboration

## Non-Goals

The Agent Runtime must never contain business-specific logic.

Business behavior belongs exclusively inside the Blueprint configuration.

## Rationale

Separating execution from business definition creates a stable runtime that can support many vertical AI solutions without architectural changes. New domains become configuration problems rather than engineering projects, reducing maintenance costs while increasing extensibility.
