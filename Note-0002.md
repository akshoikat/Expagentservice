## Channel Gateway

### Purpose

`Channel Gateway` হলো Communication Module-এর একমাত্র public entry point, যার মাধ্যমে সব external communication channel থেকে আসা event platform-এ প্রবেশ করবে।

এটি provider-specific implementation এবং business logic-এর মধ্যে একটি boundary হিসেবে কাজ করবে।

### Responsibilities

* Incoming message গ্রহণ করা।
* Provider payload-কে platform-এর canonical format-এ রূপান্তর করা।
* Channel identity যাচাই করা।
* Contact resolve বা create করা।
* Conversation resolve বা create করা।
* Normalized event Communication Module-এ পাঠানো।
* Message metadata সংরক্ষণের জন্য প্রস্তুত করা।
* Duplicate বা retry event শনাক্ত করা (idempotency support)।

### Supported Channels (V1)

```text
WhatsApp Business API
```

### Future Channels

```text
Facebook Messenger
Instagram Direct
Telegram
Gmail
Live Chat
X (Twitter)
LinkedIn Messaging
```

### Input

Provider Adapter থেকে normalized event গ্রহণ করবে।

উদাহরণ:

```text
IncomingMessageEvent
IncomingMediaEvent
IncomingStatusEvent
WebhookVerificationEvent
```

### Output

Communication Module-এর internal event publish করবে।

উদাহরণ:

```text
MessageReceived
ConversationStarted
ContactIdentified
ChannelConnected
```

### Responsibilities Excluded

`Channel Gateway` কখনও করবে না:

* AI Response Generation
* LLM Invocation
* Workflow Execution
* Knowledge Retrieval
* Memory Management
* Business Decision Making

এসব সংশ্লিষ্ট module-এর দায়িত্ব।

### Architecture Flow

```text
WhatsApp
      │
      ▼
Provider Adapter
      │
      ▼
Channel Gateway
      │
      ▼
Communication Module
      │
      ▼
Conversation Lifecycle
```

### Design Principles

* Provider-agnostic
* Idempotent
* Stateless
* Event-driven
* Extensible

### Benefits

* Communication Module provider সম্পর্কে কিছু জানবে না।
* নতুন channel যোগ করতে Communication Module পরিবর্তন করতে হবে না।
* সব channel একই Conversation lifecycle ব্যবহার করবে।
* Testing সহজ হবে, কারণ Channel Gateway-এর input এবং output নির্দিষ্ট contract অনুসরণ করবে।
